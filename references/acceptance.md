# 交稿前验收

检查的是**准备交给用户的最终源文件与对应导出图**。预览缓存、构建日志、导出成功或结构校验均不能单独代替验收。每次改动后，复查受影响的语义关系、版面和输出；最终做一次整图检查。

每轮先从用户本轮要求和仍适用的历史纠正中整理简短复查项。它们可以只记在工作记录中，不必另外制作交付文档；不能因为本轮换了布局，就忽略此前纠正过的词语堆砌、主次倒置、错位箭头或空卡片。

## 1. 逻辑与一眼识别

- [ ] 不依赖细字，能认出研究对象或核心方法，最重要概念有明显视觉重点。
- [ ] 按读图方向能说清输入、核心处理与产出；无无意义框、悬空图标和连接。
- [ ] 串行/并行/汇总/反馈与正文一致；反馈有明确终点。
- [ ] 主体与内部模块的归属明确，没有把局部详解误画成独立外部系统；用户已否定的功能未以旧连线或旧备注残留。
- [ ] 放大带来自真实局部，源与详解匹配，且不与流程箭头混淆。
- [ ] 放大范围准确：结果详解来自结果节点；源边界与展开带在缩小后仍可辨认。
- [ ] 每幅小图对应其标签；明确表达前后变化时，对应变化存在且正确；仅有拟开展流程时没有编造响应效果。
- [ ] 无虚构实验结果、未经正文支持的架构或承诺；预测、候选等限定仍然清楚。

## 2. 文字与字体

- [ ] 自拟可见文本均为单词、术语或名词性组合词，无解释句、动宾短语、括号释义和“粗体标题＋解释短句”；用户明确允许的对话问句等例外仅用于指定位置。
- [ ] 标签组成真实功能或科学关系，没有把长句删成词串；“分析流程”等标题与内部结构相符，没有用具体案例替代研究内容。
- [ ] 无不必要的缩写、重复释义和 a/b/c；必要单位、公式与原始数据含义未被误删。
- [ ] 最多三档字号；同级大小与字重相同，主体标签均加粗。引用位图的原始字号若无法统一，说明未满足项，不能直接勾选通过。
- [ ] 中文黑体、英文与数字 Arial；实际字体可用，无缺字、错字和渲染替代。
- [ ] 黑/近黑文字；只在合适的深色小块内使用白字，无杂色文本。
- [ ] 文本未溢出、裁断、挤压或自动缩小，换行合理。

## 3. 框线与配色

- [ ] 主框、常规框、内部结构线、箭头各自有稳定层级，轮廓足够清晰。
- [ ] 同级边框和箭头头型一致，端点和转折整齐；没有误触框、穿字与杂乱交叉。
- [ ] 齐平布局中的外框上下沿、标题条和箭头锚点均对齐；气泡尾角等拼接细节无断口或重边。
- [ ] 主画面白底，填色集中于标题和少量关键局部，没有大块底色压住内容。
- [ ] 用颜色映射逐项追踪输入、工具、详解和结果；同一含义无中途换色。
- [ ] 主题色和类别身份色区分清楚，前后对照没有颜色角色对调。

## 4. 紧凑、完整与参考一致

- [ ] 核心区域视觉分量足够，辅助区域没有抢占主位。
- [ ] 版面随实际内容收缩，没有为了达到参考图的密度增加句子、图标、空框或收尾模块；单行标签框的上下留白贴合文字。
- [ ] 同级元素对齐、间距稳定；模块比例随实际内容分配，不机械等分。
- [ ] 素材完整、比例正常，没有被裁掉的细胞边缘或低分辨率模糊图。
- [ ] 图标确实帮助辨认对象或功能，且人物、机器人等素材的描边、填色和细节密度一致。
- [ ] 与参考并排检查过线色、线宽、配色、字体层级、填色比例、图形语言及密度，而非只判断“风格差不多”。

## 5. 最终文件验证

- [ ] 实际最终源文件已经保存；可编辑文字和结构仍是原生对象。
- [ ] 针对导出格式检查文字、字号、字重与字体声明；PPTX 可检查对象属性或解包 XML，不能只相信生成脚本默认设置。
- [ ] 最终源文件经实际可用的 Office/LibreOffice 或相应渲染器导出；打开导出图检查，不把另一份重画的图作为最终预览。
- [ ] 放大检查裁切、文字、细线及端点，缩小到拟插入正文的尺寸检查识别与可读性。
- [ ] 预览与交付源文件内容一致，旧版本保留，用户手工修改未丢失。
- [ ] 来源、示意性质和必要说明位于备注或图注，不重新塞回图内。

若因工具限制无法完成某项实际验证，说明已检查范围和未检查项，不宣称全部合格。可修复的问题先修复，再交稿；不要把用户当作第一次检查者，也不要把验收清单变成每轮都要用户批准的新流程。
